# CHANGELOG-iOS

## v5.0 — 26.10.2026 — автосохранение в приложении с экрана «Домой»

Проблема: в приложении, установленном на экран «Домой» через Safari, прогресс не сохранялся автоматически — помогал только экспорт/импорт файла.

Причины, найденные в коде сайта:
1. **При запуске набор мог не открыться, и прогресс выглядел потерянным.** Если сохранённый зашифрованный набор не удавалось расшифровать,
   код удалял его вместе с паролем и прерывал запуск (`return`), запасные варианты не срабатывали. Приложение открывалось пустым;
   статистика при этом лежала в памяти, но к ней не было набора.
2. **Последний открытый набор подменялся старым.** Загрузка файла через боковую панель и окно «💾 Прогресс» не обновляла `ios:savedSetText`.
   При следующем запуске открывался прежний набор, а у него свой прогресс.
3. **Копия в IndexedDB отставала от ответов.** Копия писалась через 0,6 с после ответа. При сворачивании обработчик `boot.js` срабатывал
   раньше, чем `app.js` сохранял сессию. Поэтому, если смахнуть приложение сразу после ответа, последние ответы в копию не попадали.
4. **Прогресс из версии iOS 4.0 не подхватывался.** Он хранился под ключом `questions.js`. На сайте `questions.js` нет (404), а у наборов
   с GitHub ключ — хэш тем, поэтому импортированный прогресс не связывался с набором.
5. **Ошибки записи замалчивались.** `saveStats()` молча проглатывала ошибку переполнения localStorage (лимит ~5 МБ: наборы вопросов,
   черновики редактора).
6. **Обновления сайта могли не доходить до установленного приложения.** Кэш SW оставался `trainer-v4`, в нём не было `style.css`
   и `editor.js`, но были отсутствующие на сайте `questions.js` и `single/trainer.html`.

Что сделано (все места помечены комментариями «Правки для iOS (v5)» / «Правки для iOS»):
- `app.js` — новый порядок запуска: последний набор → копия набора в IndexedDB → встроенный `questions.js`. Набор при ошибке
  не удаляется. Любая загрузка набора (GitHub, зашифрованный файл, обычный файл, боковая панель) записывает его как «последний»
  и делает копию в IndexedDB. Сразу после каждого ответа и при сворачивании пишется копия в IndexedDB. Добавлена разовая миграция
  прогресса со старых ключей `questions.js` / `saved-set`: только если ≥50% вопросов совпадают. Ошибки записи статистики выводятся в консоль.
- `boot.js` — задержка копии 0,3 с вместо 0,6 с. Новая функция `backupSoon()` делает копию сразу после ответа. При
  сворачивании и закрытии копия пишется всегда. При переполнении localStorage удаляются черновики редактора, запись повторяется,
  пользователь получает предупреждение. `questions.js` стал необязательным (без ошибки в консоли).
- `ios.js` — версия 5.0. Переключение наборов в «💾 Прогресс» работает. Исправлена подсветка активного набора (ошибка приоритета
  операторов), вместо хэша показывается имя набора. Добавлена подсказка, что приложение с экрана «Домой» хранит данные отдельно
  от Safari. SW регистрируется с `updateViaCache: "none"`, обновление проверяется при каждом возвращении в приложение.
- `sw.js` — кэш `trainer-v5`, исправлен список файлов. Сетевой запрос, который не уложился в тайм-аут, всё равно обновляет кэш.
  Удаляются только старые кэши `trainer-*`.

Тесты (Playwright WebKit, эмуляция iPhone 15 Pro Max, http, постоянный профиль): 8/8 сценариев автосохранения, восстановления,
миграции и редактора, 3/3 по обновлению с v4 на v5. Ошибок JS нет.
